## 最终根因

**问题出在 D-Bus 的派发层，而不在处理逻辑。**

具体来说，是 `looper.cpp` 里的这个设计：

```cpp
int ret = poll(fds, 2, 100);                    // 100ms 超时
...
if (fds[0].revents & POLLIN) {
    (void)dbus_connection_read_write_dispatch(conn_, 0);   // 每次只派发一轮
}
```

代码注释说“若仍有数据到达，poll 会立即再次唤醒”，但实际行为是：**每次 POLLIN 只处理一轮，然后回到 poll 等待，最多需要 100ms 才轮到下一次**。

26 个监控线程以 10 秒周期向总线发送消息，它们会和外部请求**争抢同一个派发循环的轮次**。每次 poll 唤醒只派发一轮，排队的外部请求就要等下一轮。

这解释了所有现象：
- 为什么延迟是 13ms / 300ms / 1000ms / 3000ms 这种离散值：**它就是 poll 轮次的整数倍**
- 为什么 `Recv-Q` 是 0：消息已经被 `read_write_dispatch` 读进 libdbus 的**内部队列**，不在 socket 队列里
- 为什么主线程 99% 停在 `do_sys_poll`：它确实在睡，但醒来后只处理
