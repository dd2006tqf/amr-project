`sportcamera/` 是 Insta360 运动相机产品线（IAC2 = Ace Pro / CV5、IAC3 = Ace Pro 2 / CV52）的整机固件源代码工作区。整机由「Cortex-A RTOS（ThreadX）+ Cortex-A Linux + 外置 MCU + 蓝牙 SoC + 配件」多个域组成，对外通过 USB / Wi-Fi / 经典蓝牙 SPP / BLE GATT / L2CAP CoC 五条物理通道与手机 App 协作；所有控制面流量统一封装为 **UCD 协议**（Insta360 自研），数据面媒体大流量则走 **FrameShare 共享内存零拷贝**。整套通信框架被称为 **AIP3**——它跨 Linux 与 RTOS 两个 OS、跨多颗 SoC、跨多种介质，是这个仓库最重要的"主动脉"。
本仓库 `sportcamera/` 是 Insta360 运动相机产品线的整机固件源代码工作区，目前主要承载 IAC2（Ace Pro，CV5）与 IAC3（Ace Pro 2，CV52）两款产品。版本号在 `rtos/cortex_a/Insta360AIP/aip.h:21-47` 中以 Kconfig 宏区分：
#if defined(CONFIG_PROJECT_IAC2)
6. **可裁剪**。通过 `CONFIG_PROJECT_IAC2 / CONFIG_PROJECT_IAC3 / CONFIG_ENABLE_AMBALINK / CONFIG_AMBALINK_BOOT_OS / CONFIG_SOC_CV5 / CONFIG_SOC_CV52 / CONFIG_ENABLE_ISTREAMER / CONFIG_CLOUD_SDK / CONFIG_INSTA360_AIP` 等 Kconfig 开关，可在不同产品线上裁剪 Linux/AmbaLink/iStreamer/Cloud 模块。`Insta360AIP/Kconfig:1-19` 中可看到这些开关声明。

跨核通信涉及 RTOS 与 Linux 共享数据结构（FrameShare 描述符、UCD payload 头）。两边都从同一份头文件生成（FrameShare 见 `ins_mw_frame_share.h`，UCD 见 RTOS 的 `proto_handler/ucd/ucd.h` 与 Linux 的 `protoHandler/ucd/ucd.h`，protobuf schema 由 `proto_handler/protobuf/*.proto` 双端共享）。任何字段调整都要双端一起改、一起编、一起烧——这是 IAC2/IAC3 项目里跨团队最容易踩的坑之一。
10. **跨核字段调整两边一起改**：UCD 头、FrameShare 描述符、protobuf schema 都是双端共享。改了 RTOS 端不重编 Linux 端，就会出现"字段错位"导致的诡异行为。这是 IAC2/IAC3 跨团队最容易出岔的点。
